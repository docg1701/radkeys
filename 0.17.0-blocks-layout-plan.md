# Blocks Layout — Implementation Plan (0.17.0)

> The keypad grid is defined as an ordered list of blocks (sub-grids) whose
> cells consume firmware slots 0–35. Firmware and protocol are unchanged.
> Final-state spec: nothing here references prior schema versions.

## 1. Addressing model

- Firmware scans a fixed 6×6 matrix (rowPins GPIO 0–5, colPins GPIO 6–11,
  `diy.ino`) and reports `[row, col]`, both 0–5.
- Slot `n = row*6 + col`, range 0–35 — the physical identity of a key,
  shown in the apps as `n0`–`n35`.
- `app.layout.blocks` is an ordered list. Blocks consume slots contiguously
  in declaration order, row-major inside each block. Example: block 0 `2×4`
  → n0–n7; block 1 `4×6` → n8–n31; n32–n35 unassigned.
- Total block area must be ≤ 36. Unassigned trailing slots render nothing.
- Reordering blocks shifts slot ownership; the editor makes order explicit
  and every cell shows its slot, so the wiring map is always on screen.

## 2. Config schema (internal/config/config.go)

```toml
[app.layout]
[[app.layout.blocks]]
rows = 2
cols = 4
[[app.layout.blocks]]
rows = 4
cols = 6

[[screens.buttons]]
block = 0        # index into app.layout.blocks
row = 0          # row INSIDE the block
col = 1
label = "Copy"
action = "copy"
```

```go
type Layout struct {
    Blocks []Block `toml:"blocks"`
}

type Block struct {
    Rows int `toml:"rows"`
    Cols int `toml:"cols"`
}

type Button struct {
    Block   int    `toml:"block"`
    Row     int    `toml:"row"`
    Col     int    `toml:"col"`
    // Label, Action, Target, Content unchanged
}
```

### Slot math (config package)

```go
func (l Layout) SlotCount() int                       // Σ block areas
func (l Layout) SlotOf(block, row, col int) int       // offset + row*cols + col
func (l Layout) LocateSlot(n int) (block, row, col int, ok bool)
func MatrixSlot(row, col int) int                     // firmware (row,col) → slot
```

Input path: device `(row,col)` → `MatrixSlot` → `LocateSlot` →
`Screen.ButtonAt(block, row, col)`. Display path: iterate blocks/cells →
`SlotOf` → caption `n<slot>`.

### Validation (Issues)

- `IssueNoBlocks` — `app.layout.blocks` must declare ≥ 1 block. No defaults:
  a config without blocks is invalid, not silently repaired.
- `IssueBlockDimOutOfRange` — block rows/cols < 1 (Detail carries which).
- `IssueTooManySlots` — Σ area > 36 (Detail = total).
- `IssueUnknownBlock` — button.block out of range.
- `IssueOutOfGridRow/Col` — bounds are the button's block dims.
- `DuplicatePosition` key is `[3]int{block, row, col}`.
- `Issue.Error(layout Layout)` — position formatters read the offending
  block's dims from the layout. `Layout.Columns/Rows` and their two issue
  kinds are deleted.
- `Screen.ButtonAt` / `ButtonIndex` take `(block, row, col)`.
- `DefaultConfig()` starter ships one `6×6` block.

## 3. Host UI (internal/ui/ui.go)

- `appUI.cols/rows` deleted. Keypad = `container.NewHBox` of block frames;
  each frame = `container.NewVBox(caption, container.NewStack(strokeRect,
  container.NewPadded(grid)))` with `grid = container.NewGridWithColumns(
  block.Cols)` and caption `Block i · n<start>–n<end>`.
  `u.blockGrids []*fyne.Container` lets `renderGrid` refill cells without
  rebuilding frames. (APIs verified on docs.fyne.io: NewGridWithColumns,
  NewHBox/VBox, NewPadded, NewStack, canvas.Rectangle StrokeColor/
  StrokeWidth/CornerRadius — all in fyne v2.7.)
- Alignment checkpoint: verify HBox cross-axis behavior renders frames
  top-aligned; if not, wrap each frame in `container.NewBorder`. Decide
  visually, do not guess.
- `renderGrid`: nested loop per block/cell → `ButtonAt(block, r, c)` →
  button or placeholder rect. Host buttons keep clean labels.
- `press`: device (row,col) → slot → block-local lookup; slot without owner
  → `status.slot_unassigned` flash + log.
- Settings screen: layout entries deleted — layout describes wiring and is
  edited in radkeys-config, not in the host. Keypad rebuild hook goes with
  them.

## 4. Editor (internal/editor/)

- Shared frame builder (e.g. `internal/ui/gridframe`) used by host and
  editor so the two never diverge.
- `grid.go`: one framed grid per block. Filled cell:
  `n<slot> · <label> · <action>`; empty cell: `n<slot> +` — the slot is
  visible before assignment (wiring guide). Out-of-grid strip lists buttons
  whose (block,row,col) has no cell.
- `appsettings.go`: blocks section — one row per block (rows entry, cols
  entry, remove button) + add-block button. Every edit marks dirty and
  re-renders.
- `editor.go`: `resizeBlock(i, rows, cols)`, `addBlock()`, `removeBlock(i)`;
  selection state gains `block`.
- `inspector.go`: block selector moves the button to the first free cell of
  the chosen block; if none is free, position stays and a problem is shown.
- `problems.go`: `issue.Error(e.cfg.App.Layout)` per the new signature.

## 5. i18n (internal/i18n/i18n.go, 7 languages)

`editor.block_slots` (`"slots n%d–n%d"`), `editor.no_free_cell`,

Validation errors stay plain English, as they are today.

## 7. Tests

- config: `SlotOf`/`LocateSlot` round-trip (n0, n35, block boundary,
  unassigned); validation for no-blocks, dim < 1, Σ > 36, unknown block,
  per-block out-of-bounds, duplicate cell; Save/Load round-trip. Fixtures
  rewritten in blocks syntax.
- ui: press resolves device (row,col) → slot → block-local button;
  unassigned slot flashes status without panic or focus steal (existing
  invariant test unchanged).
- editor: cell count = Σ areas; empty-cell label shows slot;
  resize/add/remove block; `issuesAt` keyed by (block,row,col).
